Aqk[5,2] should depend only on tokens 0–5. Separately rounding the rescaled operands to BF16 can make it depend on future gates.

Write at 2, decay, read at 5

Aqk[5,2] = Σd q5,d k2,d 2G5,d − G2,d,  G5 − G2 = δ₃ + δ₄ + δ₅

Token 2 decays the state, then writes z₂. Query 5 reads that correction after per-channel decays δ₃, δ₄, δ₅ — not δ₂. This weight multiplies z₂, not raw v₂; no softmax.

The mask keeps [5,2]; only j > i is dropped.

Split the decay for GEMM

2G5 − G2 = 2G5 − r · 2r − G2
Q̃5,d = q5,d 2G5,d − rd,  K̃2,d = k2,d 2rd − G2,d
Aqk = mask(Q̃ K̃⊤)

The per-channel decay belongs inside the sum, not after QK⊤. Splitting it into query-only and key-only factors lets us prepare each row once and use a GEMM.

Any rd cancels algebraically, including zero. We choose a reference to keep the factors in range, not to make the decay separable. Each channel shares one rd across the block.

G₈ cancels exactly, but looks ahead of row 5

G5 − G8 = −(δ₆ + δ₇ + δ₈) ≥ 0
G8 − G2 = δ₃ + δ₄ + δ₅ + δ₆ + δ₇ + δ₈ ≤ 0
sum = δ₃ + δ₄ + δ₅ − δ₆ − δ₇ − δ₈ + δ₆ + δ₇ + δ₈ = G5 − G2 ✓

Row 8 supplies the reference for this 16-row block. In exact arithmetic the red terms cancel: multiplying a factor ≥ 1 by one ≤ 1 gives the original decay.

For row 5, δ₆–δ₈ are future increments. Every row i < 8 uses a reference that looks ahead; rows 8–15 do not. The mask only removes j > i, not this operand dependence.
